# Key-paper audit integrity

Run `python3 scripts/audit_key_paper_coverage.py` to generate both reports, or add
`--check` for a read-only freshness/integrity check. All paths are resolved against
the repository root. No network services are used.

The checklist is `data/manual/key_papers.csv`, not the historical enriched copy.
The sole public bibliography is `web/data/public_preview_papers.json`. The map
JSON contains paper–institution relationships, not the coverage registry.
Checklist row totals retain variants and repeated checklist entries; they are not
a count of distinct scientific works. Public mapped-paper totals count matched
bibliography rows once, independently of the number of marker relationships.

Exact matching uses DOI, arXiv ID, OpenAlex ID, then normalized exact title.
Explicit merged-version identifiers in source metadata are supported. Multiple
exact matches require review; conflicting identifiers prevent title matching.
Title normalization folds case, punctuation and dash variants. Fuzzy candidates
require length ratio >= 0.45, token overlap >= 0.65 and SequenceMatcher score >=
0.90. They are suggestions only and never establish bibliography coverage.
Historical enrichment suggestions are not promoted to confirmed identities.

Coverage statuses are `covered_as_map_marker`,
`covered_in_public_preview_paper_list`, `candidate_only`,
`missing_from_candidate_pool`, `possible_title_match_failure`, and `excluded`.
`in_public_preview` is a compatibility alias for bibliography membership.
`missing_stage` is a compatibility alias for `coverage_status`.
Missing affiliation, missing coordinates, unresolved institution, and export-rule
blockers are separate diagnostics when supplied by source metadata. When evidence
does not establish the blocker, `marker_blocker_unresolved` explicitly records
that uncertainty instead of guessing coordinates or affiliation failures.
Exclusion matching reuses the active authoritative exclusion registry and its
existing matching rules, preserving the matched exclusion rows as evidence.

Both report renderers consume one computation. The Markdown includes a SHA-256
of all seven required input files; missing files fail closed. Validation recomputes
both artifacts and compares their exact bytes, catching stale counts, row changes,
old vocabulary, exclusion changes, and missing files. Every marker must resolve
to exactly one bibliography row; there are no allowed orphan-marker exceptions.
The default public-preview CLI validator also performs this audit check. Its
in-memory dataset validator remains usable before reports are generated, and
explicit alternative dataset paths do not validate unrelated repository reports.

The generated CSV remains at `data/manual/key_paper_coverage_report.csv` for
compatibility with Admin and diagnostic consumers. It is a legacy generated
output explicitly regenerated by this maintenance task, not a human correction
file. The checklist, curated decisions and other manual inputs are read-only.

CLI refresh and Admin full refresh regenerate the quality report, author mapping
report and both coverage reports before final public validation. Admin Publish
uses that same full-refresh sequence; both audit files belong to its snapshot,
rollback and publish output registry. CLI refresh also restores all five report
files and both public JSON files on a failed step. Admin coverage queues suppress
bibliography-covered entries, while separate marker diagnostics remain available.

Admin background preview synchronization also regenerates these reports and
validates them through the `export_preview` workflow. The quality report uses
the same bibliography matcher to count unique mapped papers, avoiding splits
when marker records carry different identifiers for one bibliography entry.

The seventh input, `data/manual/key_paper_reconciliation.json`, records explicit
source-backed identity decisions against exact snapshots of the original
checklist rows. Stale snapshots fail closed. Resolved identifiers do not imply
coverage: the paper must still match the current bibliography. Reviewed distinct
titles suppress only that specific fuzzy suggestion; ambiguous cases remain
review-only. Original checklist titles and years remain visible alongside
resolved metadata and evidence. The author-mapping report reads the same
effective checklist so earlier titles retain their key-paper designation.
